# Movement and utility fidelity pass

Movement remains a fixed 128 Hz Source-style reconstruction. The existing acceleration, friction, jump ordering and split gravity are retained; these follow the pinned shipped convars in [the native data snapshot](https://github.com/SteamTracking/GameTracking-CS2/blob/5278de99318192d682ec7f0e1cc3ea9449f10c6e/DumpSource2/convars.txt) and [Valve's SDK movement reference](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/shared/gamemovement.cpp). Current subtick processing is not reproduced. Legacy stamina is intentionally absent because this snapshot disables `sv_legacy_jump`.

Player collision is separate from view height: 16 Source units half-width, 72/54 standing/crouched hull, 64/46 eye heights. These are Counter-Strike architectural dimensions, not measurements of the proprietary current executable. Map triangles and the existing continuous horizontal hull solver remain authoritative for ramps, steps and cover. Repeated duck presses always remain actionable; they slow the authored transition and recover over the pinned 0.4-second interval. Releasing duck cannot immediately grant full running speed while the player is still crouched. Native duck-speed fatigue, surface friction, ladders and water remain approximations or unsupported.

Grenades use the pinned throw-velocity parameter, historical Source launch construction (0.9 velocity scale, 30–100% strength, pitch correction, 1.25 inherited player velocity, lowered underhand origin), and a swept hand-release offset. These launch formulas are explicitly reconstructed, not extracted CS2 server logic. Dust II uses a continuous two-Source-unit sphere sweep against triangle faces, edges and vertices, including dedicated grenade clips and excluding player-only clips. The solver consumes the remaining fixed-step time after each bounce (four-contact budget), uses half-step gravity, settles on walkable floors and suppresses bounce-audio chatter below an impact threshold/80 ms spacing. The fallback practice geometry retains its ray-based contact approximation.

Native grenade sound clips and spatial acoustics remain bundled. Smoke uses the existing bounded depth-composited renderer and bullet/HE clearing. Fire uses three overlapping procedural flame billboards per damage cell, and HE uses short dust/flash cards, replacing the old lit spheres. These are inexpensive visual reconstructions; Source2 particle graphs, volumetric inferno propagation and native smoke simulation are not executed. Damage, ownership, friendly-fire rules, cover tests, detonation and smoke/fire extinguishing remain in the existing simulation path. All owned effect materials, geometry and instance buffers are disposed on expiry/reset.

Validation includes analytic swept contacts (face, edge, vertex, separation), launch strengths/momentum, energy loss/rest, and actual two-contact traversal within one game tick. Chromium checks exercise real movement input, jump/crouch recovery, native stairs and carrier support, grenade handling/damage, skin sharing, idle motion and shader rendering. Screenshots are generated in ignored `artifacts/`.
