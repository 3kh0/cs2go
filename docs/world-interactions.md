# Player and world interactions

Right click with the M4A1-S or USP-S to attach/remove its suppressor. Native v6 viewer animations and their embedded attachment/visibility markers drive hands, suppressor visibility, state changes, and screw sound cues. Firing/reloading are locked for the animation; switching, losing pointer lock, death, and bomb/utility actions cancel it. Cancellation before the attachment marker keeps the previous state; cancellation after it preserves the committed state. Weapon switching cannot skip the remaining attack cooldown.

Suppression selects the imported primary/alternate accuracy and recoil parameters, native suppressed/unsuppressed shot recordings, muzzle flash and tracer visibility. The MP5-SD remains permanently suppressed. Dropping, picking up, bot scavenging, spectating, takeover, and surviving a round retain the item's attachment state; newly purchased guns start attached. Native clips come from `python3 scripts/import-suppressors.py`, with URLs/hashes in `packages/assets/public/models/viewmodels/suppressor-source.json`. The existing pinned Steam depot supplies sound recordings via `scripts/import-cs2-weapon-audio.py`; unchanged verified encodes are retained on regeneration. Native gain layers, precise current runtime attack timing and bot hearing remain approximations.

Competitive and range modes now collide with living bot hulls horizontally and support landing on their heads for boosts. Dead bodies do not provide player support. The casual movement path keeps its existing nonblocking behavior. Actor dimensions still follow the browser movement controller; this is not the full native player hull/duck-fatigue implementation.

Dust II's native soccer ball is detached from its static render batch and responds to player/bot contact and player shots. It uses the existing native mesh/material, bounded sphere collision substeps, bounce, rolling, sleep, and round reset. Source evidence: the pinned map entity dump identifies `models/props/de_dust/hr_dust/dust_soccerball/dust_soccer_ball001.vmdl` as its one `prop_physics_multiplayer`, at Source position `[-1203.060059, -368, 136.057999]`. The compiled model supplies a centered 7.9-Source-unit collision sphere (0.20066 m), replacing render-bound inference; its hashed `soccerball` surface supplies elasticity 0.25. `python3 scripts/import-world-ball.py --cli /path/to/Source2Viewer-CLI` verifies the pinned VPK and records both source resource hashes in `apps/game/src/data/world-ball.json`. Native mass (1), damping and surface friction are retained as evidence; this browser solver does not equate those fields with an invented native rolling law. The contact-pair restitution rule, contact/shot impulses, rolling resistance, sleep thresholds and rotation remain approximations. Breakable objects are excluded. The imported Dust II entity dump contains no ladder entities; ladder/water traversal and general-purpose Source rigid-body physics are not implemented.

The detached ball owns its material and no longer carries static-map lightmap attributes or shader hooks. Its current position samples the existing actor ambient cube, baked sun visibility and nearest local reflection map, so rolling through shade does not retain its original baked vertex-light pattern. These are the same bounded probe/reflection approximations used for other actors, not native rigid-body rendering parity.

Validation: `bun run test src/suppressor.test.ts src/actor-collision.test.ts src/world-ball.test.ts`; `bun run test:browser tests/interactions.spec.ts` exercises actual right-click animation, shot audio selection, cancellation, pickup persistence, boost support, jump/death support removal, and the native ball.
